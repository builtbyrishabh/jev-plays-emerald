# Jev Plays Emerald

Watch Jev play a real Pokémon Emerald game, with the Stone Badge in Rustboro as its next goal. Jev chooses meaningful actions; optional Luna coaching helps when progress stalls. See [first-gym implementation and evidence](docs/first-gym.md) for what has actually been verified.

Jev chooses every move of the game: which door to walk through, who to talk to, which starter to take, and how to fight. Python enumerates what is mechanically possible on the current map - its exits, people and signs - and reuses PokéBot Gen3 navigation, menus, healing, and emulator inputs to carry the choice out. Gender selection, the clock menu and mandatory cutscene dialogue are deterministic; Jev confirms the requested player name. There is no hardcoded route.

## Run locally

The verified target is Apple Silicon macOS, Python 3.13, and the unmodified English Emerald ROM with SHA-1 `f3ae088181bf583e55daf962a92bb46f4f1d07b7`.

```bash
brew install mgba
python3.13 scripts/bootstrap.py
```

Put your Vercel AI Gateway key in the ignored `.env` as `AI_GATEWAY_API_KEY`, then launch with your ROM path:

```bash
uv run --env-file .env python -m jev_plays_emerald --rom "roms/Pokemon - Emerald Version (USA, Europe).gba"
```

Open **<http://127.0.0.1:8888/jev/index.html>** for gameplay, decisions, probabilities, HP, and pause/resume. Real Jev calls use your gateway account. ROMs, saves, keys, and recordings stay outside Git.

Existing profiles and saves are preserved. Use `--profile new-run-name` for a separate fresh run. See [setup](docs/setup.md) for dependencies and checkpoint handling, and [viewer details](docs/viewer.md) for controls.

For local Luna coaching, run `pnpm --dir service install` and sign into the
Codex CLI with ChatGPT (`codex login`). Prefix the launch command with
`JEV_PLANNER_BACKEND=codex JEV_PLANNER_MODEL=gpt-5.6-luna` and use a fresh `--profile first-gym-run`. The default target is `first-gym`; pass `--target rival` for the original opening. This uses your
subscription capacity for Luna; Jev still uses AI Gateway. It never silently
falls back to Luna API billing. See [Codex planner setup](docs/codex-planner.md).

For explicit API-based planning instead, set `JEV_PLANNER_BACKEND=gateway`
and `JEV_PLANNER_MODEL=openai/gpt-5.6-luna`. Jev's base prompt contains no authored
route. The planner advises after three repeats of one action or eight meaningful
overworld decisions without story progress. Each correction contains a currently legal
action, exact location, action to avoid, and observable success signal. Once Jev
completes that action, the hint expires and Jev decides independently until another
stall. Jev still chooses every action. Advice and call count appear in
the viewer.

Planner hypotheses and observed outcomes persist for inspection in
`runs/planner-memory.json`; saved routes and dead ends are not replayed into model prompts. This local run does not need a database; replace the
ledger only if multiple games or concurrent writers need shared memory. See
[planner behavior and limits](docs/planner-proposal.md).

Jev confirms the requested player name **Jev** through its decision API. The
keyboard routine enters that exact capitalization; the name is user-specified,
not freely generated by the model.

Jev also receives a bounded transcript read from Emerald's live dialogue
buffer. To test Jev without Luna, leave `JEV_PLANNER_MODEL` unset. Mandatory
text still advances automatically; Jev uses what was said and the observed game
state when choosing the next meaningful action.

## Scope and evidence

Earlier builds completed continuous input-only New Game-to-rival runs with real
Jev decisions. The final no-authored-route prompt has not yet reproduced that
result within its bounded verification run. Completion still requires the actual
rival battle victory and a newly set story flag; loading a completed checkpoint
does not count as a new win.

See [measured results](docs/results.md) for repeatability, failures, costs, and remaining limitations. A working integration does not establish that Jev outperforms deterministic rules.

The app uses pinned mGBA/PokéBot Gen3, Python, and one local server with plain HTML/CSS/JavaScript. Optional Luna coaching uses the existing TypeScript child, with either bounded headless Codex calls or explicit AI Gateway calls. There is no database or persistent coding session in the gameplay loop.

Fresh, bounded comparison runs and response-level token reports are available
through [the benchmark workflow](docs/benchmark.md). The
[post notes](docs/post-notes.md) distinguish measured results from claims the
experiment cannot support.
